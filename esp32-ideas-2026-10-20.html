ESP32 Energy Harvesting — IoT ไม่ต้องเปลี่ยนถ่านอีกต่อไป

🌞 Solar + Deep Sleep: สูตรสำเร็จสำหรับ Sensor Node แบบไม่ต้องใช้ไฟบ้าน

แนวคิดหลักของ ESP32 Energy Harvesting ในปี 2025-2026 คือการจับคู่ แผง Solar Cell ขนาดเล็ก เข้ากับ Deep Sleep Mode ของ ESP32 เพื่อให้ node รายงานข้อมูลได้ตลอดชีพโดยไม่ต้องเดินสาย ไม่ต้องเปลี่ยนแบตเตอรีเลย แต่ต้องออกแบบวงจรและ firmware ให้ประหยัดพลังงานสูงสุด

Solar Cell Deep Sleep LiPo Charging Sensor Node

⚙️ สถาปัตยกรรมวงจร Solar IoT Node

วงจรพื้นฐานที่ใช้ได้จริง:

  • Solar Panel (6V 1W) → ชาร์จ IC (TP4056 หรือ BQ25504)
  • LiPo/Li-Ion 3.7V เป็น buffer สำรองพลังงาน
  • Step-down หรือ LDO → 3.3V สำหรับ ESP32
  • ESP32 วัดค่า sensor → ส่ง MQTT/HTTP → นอน deep sleep
  • ตื่นทุก 5-15 นาที ใช้ไฟเพียง ~10µA ขณะนอน
TP4056 BQ25504 3.3V LDO

💡 ESP32-S3 PowerFeather Board

บอร์ดที่ออกแบบมาสำหรับ energy harvesting โดยเฉพาะ มี LiPo charger + solar input + battery monitor ในตัว ใช้กับ ESP32-S3 ที่มีประสิทธิภาพ Deep Sleep ดีกว่า ESP32 รุ่นแรก อยู่ที่ราว 7µA ขณะ sleep

  • Solar input ในตัว ไม่ต้องต่อวงจรชาร์จเพิ่ม
  • Battery voltage monitoring ผ่าน ADC
  • รองรับ LiPo + Li-Ion หลายขนาด
  • Deep Sleep ลึกถึง ~7µA
ESP32-S3 PowerFeather 7µA Sleep

📡 Vibration Energy Harvesting (VEH)

งานวิจัย arXiv 2025 ชี้ว่า VEH เหมาะกับสภาพแวดล้อมที่ไม่มีแสงแดด เช่น ในโรงงาน ใต้สะพาน หรือในอุโมงค์ โดยเก็บพลังงานจากการสั่นสะเทือนของเครื่องจักร ข้อจำกัดหลักคือ ambient vibration มักเป็นแบบ intermittent ทำให้ harvest ได้ไม่สม่ำเสมอ ต้องมี buffer capacitor ขนาดใหญ่

⚠️ VEH ยังต้องใช้คู่กับ super-capacitor ใหญ่ หรือ LiPo ขนาดเล็กเป็น buffer — ไม่สามารถจ่ายไฟให้ ESP32 โดยตรงได้

🔌 RF Energy Harvesting — ยังเป็น Niche

การเก็บพลังงานจากคลื่น RF (WiFi, LTE, LoRa ambient) ยังให้กำลังน้อยมาก ไม่เพียงพอสำหรับ ESP32 โดยตรง ใช้ได้แค่เป็นแหล่งพลังงานเสริมสำหรับ ultra-low-power sensor node ที่ตื่นน้อยมาก หรือสำหรับ passive RFID-like sensor

RF Harvesting Passive IoT Ambient Energy 
// ตัวอย่าง Deep Sleep Loop สำหรับ Solar Sensor Node
#include <esp_sleep.h>
#define SLEEP_MINUTES 10  // ตื่นทุก 10 นาที

void setup() {
  readSensors();         // อ่าน sensor
  sendMQTT();            // ส่งข้อมูล
  WiFi.disconnect();     // ปิด WiFi ก่อนนอน
  esp_deep_sleep(SLEEP_MINUTES * 60 * 1000000ULL);  // หน่วยเป็น microseconds
}
void loop() {}  // ไม่เคยถูกเรียก เพราะ deep sleep reset ทุกครั้ง

ESP32 Industrial Automation — MODBUS RTU/TCP Gateway

🔧 ESP32 เป็น Low-Cost Industrial Gateway ได้จริงหรือ?

ในปี 2025-2026 มีโปรเจกต์ชุมชนจำนวนมากที่ใช้ ESP32 เป็น Modbus RTU → TCP/MQTT Gateway เชื่อม PLC, inverter, energy meter, VFD รุ่นเก่าเข้ากับระบบ Home Assistant, SCADA หรือ cloud โดยต้นทุนต่ำมากเมื่อเทียบกับ industrial gateway เชิงพาณิชย์

📦 Hardware ที่ต้องใช้

  • ESP32 (รุ่นไหนก็ได้ที่มี UART)
  • MAX485 / MAX3485 TTL→RS-485 transceiver
  • Resistor 120Ω (termination) หัวท้ายสาย
  • Shielded twisted pair cable
  • Power supply 5V หรือ 12V สำหรับ industrial device
MAX485 RS-485 UART

🗺️ โปรเจกต์จาก Hackster.io

ESP32 + LAN8720A Ethernet PHY เพื่อทำ Modbus RTU → TCP Gateway แบบมีสาย (ไม่ใช้ WiFi) เหมาะกับ environment อุตสาหกรรมที่มีสัญญาณ RF รบกวน stack: RS-485 → Modbus RTU → ESP32 → Ethernet → Modbus TCP → Home Assistant / SCADA → MQTT Broker

LAN8720A Modbus TCP Home Assistant

🏗️ Industrial Shields ESP32 PLC

บอร์ด PLC เชิงพาณิชย์ที่ใช้ ESP32 เป็น core มีครบ: RS-485, Modbus RTU/TCP, WiFi, BLE, Digital I/O, Analog I/O ใน form factor มาตรฐาน DIN-rail ราคาถูกกว่า Siemens S7 หลายเท่า เหมาะสำหรับ SME automation

PLC DIN-Rail Industrial Grade

📷 ESPuno + Seeed Modbus Vision Camera

Seeed Studio เปิดตัว Modbus Vision RS485 Camera ที่ใช้ ESP32-C3 เป็น core — กล้องที่ตอบสนองต่อ Modbus command โดยตรง เหมาะสำหรับ factory line inspection, barcode reading, quality control โดยไม่ต้องมี PC

💡 ESPuno Pi Zero (ESP32-C6) รองรับ input 60V DC + RS-485 ในตัว เหมาะกับ industrial power rail โดยตรง
// Modbus RTU Master บน ESP32 ด้วย library esp32ModbusRTU
#include <esp32ModbusRTU.h>

esp32ModbusRTU modbus(&Serial2, 4);  // DE/RE pin = GPIO4

void setup() {
  Serial2.begin(9600, SERIAL_8N1, 16, 17);  // RX=16, TX=17
  modbus.begin();
  // อ่าน Holding Register จาก slave ID=1, register 0x0000, 2 registers
  modbus.readHoldingRegisters(1, 0x0000, 2);
}

ESP32-C6 — Triple Radio: WiFi 6 + BLE 5 + Zigbee/Thread

🔮 ชิปเดียว ครอบคลุมทุก Smart Home Protocol

ESP32-C6 คือชิปเดียวที่รองรับ WiFi 6 (802.11ax), Bluetooth 5.0 LE และ 802.15.4 (ซึ่งรองรับทั้ง Zigbee 3.0 และ Thread 1.3) ในชิปเดียว ทำให้สามารถสร้างอุปกรณ์ Matter-ready, Zigbee coordinator หรือ Thread border router ได้โดยไม่ต้องใช้ module เสริมใดๆ

WiFi 6 BLE 5.0 Zigbee 3.0 Thread 1.3 Matter

📶 WiFi 6 (802.11ax) คืออะไร?

  • OFDMA: ส่งข้อมูลหลาย device พร้อมกัน
  • MU-MIMO downlink: AP ส่งให้ device หลายตัวพร้อมกัน
  • Target Wake Time (TWT): device ตื่นรับข้อมูลเป็นช่วงเวลาที่กำหนด ประหยัดแบตมาก
  • Dense environment: router เดียวรองรับ device ได้มากขึ้น

🏠 Use Case: Zigbee Smart Home

  • ใช้เป็น Zigbee Coordinator โดยไม่ต้อง hub แยก
  • Control Zigbee bulb, sensor, switch ผ่าน ESP32-C6
  • Tutorial: ShillehTek "Zigbee Light Switch Network"
  • เชื่อมกับ Home Assistant ผ่าน MQTT
Zigbee Coordinator Home Assistant

🌐 ESP32-C5: Dual-Band Variant

  • รองรับ 2.4 GHz + 5 GHz WiFi 6
  • Zigbee 3.0 + Thread 1.4 (ใหม่กว่า C6)
  • เหมาะกับ environment ที่ 2.4 GHz แออัด
  • ยังอยู่ในช่วง early adoption ปี 2025-2026
5 GHz Dual-Band Thread 1.4

🔋 TWT = Battery-Friendly IoT

Target Wake Time ช่วยให้ ESP32-C6 กำหนดตารางเวลาตื่นรับข้อมูลกับ AP ล่วงหน้า ไม่ต้องคอยรับ beacon ตลอดเวลา ลด duty cycle radio ลงได้มาก เหมาะกับ battery-powered sensor ที่ต้องการ latency ต่ำแต่ประหยัดพลังงาน

✅ TWT เป็น feature สำคัญที่ WiFi 5 ไม่มี — เหตุผลหลักที่ควรเลือก ESP32-C6 สำหรับ battery device

🔗 Matter Bridge Device

ใช้ ESP32-C6 สร้าง Matter Bridge ที่รวม Zigbee + Thread อุปกรณ์เก่าที่ไม่รองรับ Matter เชื่อมเข้า ecosystem Apple HomeKit, Google Home, Amazon Alexa ได้โดยไม่ต้องซื้อใหม่

Matter Bridge Legacy Device

📊 เปรียบ ESP32-C6 vs C3 vs S3

  • C3: WiFi 4 + BLE 5, ราคาถูกที่สุด
  • S3: WiFi 4 + BLE 5 + AI accelerator, camera
  • C6: WiFi 6 + BLE 5 + Zigbee/Thread ✓
  • เลือก C6 เมื่อต้องการ Matter/Thread/Zigbee

Air Quality Sensor Stack 2026 — วัดอากาศครบครัน

🏆 Stack แนะนำ: SCD41 + SGP41 + PMS5003 + SHT45

ชุด sensor ที่ครอบคลุมการวัดคุณภาพอากาศครบที่สุดสำหรับ ESP32 ในปี 2026 ทุก sensor ในชุดนี้ได้รับการรองรับโดย ESPHome โดยตรง สามารถเพิ่มเข้า Home Assistant ได้ใน 5 นาที ไม่ต้องเขียน code custom

Sensor วัดอะไร Protocol ข้อดีหลัก ข้อควรระวัง
SCD41 CO₂ จริง (NDIR) + Temp + Humidity I2C CO₂ แม่นยำ 0-5000 ppm, ไม่ใช่ estimate ราคาสูงกว่า ~$30-40
SGP41 VOC Index + NOx Index I2C วัด NOx ได้ (SGP40 ไม่มี) ต้องใช้ SHT สำหรับ humidity compensation
ENS160 VOC (TVOC) + eCO₂ estimate I2C / SPI ราคาถูก ~$5-8, ESPHome ready eCO₂ เป็นแค่ estimate ไม่ใช่ค่า NDIR จริง
PMS5003 PM1.0, PM2.5, PM10 UART 9600 ราคาถูก ~$15, ใช้งานง่าย มี fan → มีเสียงรบกวนเล็กน้อย
PMS7003 PM1.0, PM2.5, PM10 + 0.3-10µm counts UART 9600 ข้อมูลละเอียดกว่า PMS5003 ต้องระวัง wiring fan connector
SHT45 Temp ±0.1°C + Humidity ±1% I2C แม่นยำสูงสุดในตระกูล SHT, ใช้ compensate gas sensor ราคาสูงกว่า SHT30

🔬 ENS160 vs SCD41 — เลือกอะไร?

  • ENS160: ถูก ใช้งานง่าย เหมาะ home automation ทั่วไป
  • SCD41: แม่นยำกว่า เหมาะ lab, greenhouse, CO₂ monitoring จริงจัง
  • ENS160 eCO₂ เป็นการ estimate จาก VOC ≠ NDIR จริง
  • ถ้าสำคัญ: ใช้ SCD41 ถ้าประหยัด: ENS160
ESPHome Home Assistant

📡 SGP41 — VOC + NOx ในชิปเดียว

Sensirion SGP41 เพิ่ม NOx index จาก SGP40 เดิม ทำให้วัดทั้ง Volatile Organic Compounds และ Nitrogen Oxide ได้ในชิปเดียว ใช้ algorithm RHT compensation ต้องอ่านค่า SHT sensor ก่อนส่งให้ SGP41 คำนวณทุกครั้ง

💡 ใช้ SGP41 + SHT45 ด้วยกันเสมอ เพื่อให้ compensation ถูกต้อง

🌫️ PMS5003 Wiring ที่ถูกต้อง

  • VCC = 5V (ไม่ใช่ 3.3V!), TX → ESP32 RX
  • ต้องใช้ logic level shifter หรือ voltage divider
  • อ่าน UART ที่ 9600 baud, 8N1
  • ข้อมูล 32 bytes: start byte 0x42 0x4D
  • Library: PMS Library, ESPHome pmsx003
5V Power Level Shifter UART

ESP32 Mesh Networking — painlessMesh vs Mesh-NOW

🌐 Mesh Network คืออะไร และทำไมต้องใช้?

ปัญหาหลักของ IoT node ที่อยู่ไกลจาก router คือสัญญาณ WiFi ไม่ถึง Mesh Network แก้ปัญหานี้โดยให้ ESP32 แต่ละตัวทำหน้าที่เป็น relay node — ข้อมูลจาก node ที่ไกลที่สุดส่งผ่าน node กลางๆ ก่อนถึง gateway ทำให้ครอบคลุมพื้นที่ขนาดใหญ่ได้โดยใช้ ESP32 ราคาถูก

🔵 painlessMesh (Arduino)

  • Library: painlessMesh v1.4.5 ใน Arduino Library Manager
  • รองรับ ESP32 + ESP8266 ในเครือข่ายเดียวกัน
  • Auto node discovery, multi-path routing
  • Node recovery อัตโนมัติเมื่อ node หลุดออก
  • Alteriom fork: เพิ่ม SensorPackage, CommandPackage, StatusPackage + time sync
  • License: GPL 3.0, ชุมชนใหญ่
Arduino WiFi Mesh Community

🟢 Mesh-NOW (ESP-IDF)

  • ESP-IDF Component Registry (ใหม่ปี 2025)
  • ใช้ ESP-NOW เป็น transport (ไม่ใช่ WiFi)
  • Auto-discovery, multi-hop routing
  • AES-128-GCM encryption ในตัว
  • Message queue ป้องกันข้อมูลหาย
  • รองรับ ESP32, S2, S3, C3, C6 (ESP-IDF v4.4+)
ESP-NOW AES-128 ESP-IDF

⚖️ เลือกใช้ Library ไหน?

  • ใช้ Arduino IDE → painlessMesh เหมาะกว่า
  • ต้องการ security / encryption → Mesh-NOW
  • ต้องการ range ไกลกว่า WiFi → Mesh-NOW (ESP-NOW range ดีกว่า)
  • ชุมชนใหญ่ / มี tutorial เยอะ → painlessMesh
  • ESP-IDF codebase → Mesh-NOW

📶 ESP-NOW vs WiFi Mesh

  • ESP-NOW: connectionless, latency ต่ำกว่า, range ไกลกว่า
  • ESP-NOW: ไม่ต้องมี router ทำงานได้อิสระ
  • WiFi Mesh: bandwidth สูงกว่า, รองรับ data ขนาดใหญ่
  • ESP-NOW payload: max 250 bytes/packet
  • เหมาะกับ sensor data ขนาดเล็ก เช่น temp, humidity, motion
✅ สำหรับ IoT sensor network ทั่วไป ESP-NOW Mesh มักดีกว่า WiFi Mesh เพราะ latency ต่ำ range ไกล และประหยัดพลังงานกว่า
// painlessMesh — Hello World
#include "painlessMesh.h"
painlessMesh  mesh;

void receivedCallback(uint32_t from, String &msg) {
  Serial.printf("Received from %u: %s\n", from, msg.c_str());
}
void setup() {
  mesh.init("MESH_SSID", "MESH_PASS", 5555);
  mesh.onReceive(&receivedCallback);
}
void loop() {
  mesh.update();
  mesh.sendBroadcast("Hello from node!");
  delay(1000);
}
